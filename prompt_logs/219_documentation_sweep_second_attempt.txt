Date: 2026-07-12

User: "make a documentation consistency sweep"

Context: the first attempt (prompt log 218) failed. Five agents were given
edit access and a brief that told them to record corrections with dates.
They wrote ABOUT the documentation INSIDE the documentation, added sections
outside each document's purpose, and denormalized content across files. The
user caught it document by document. I then compounded it by reverting his
corrections along with the damage; everything was restored from a backup

METHOD THIS TIME, chosen deliberately to make that failure impossible:

1. Agents get READ-ONLY access. They REPORT; they do not edit. Every edit
   is made by the orchestrator, by hand, and shown to the user.
2. A finding is only a finding if it is one of:
     (a) a FACT that is wrong or out of date (a claim the computations have
         since settled or refuted; a number that changed; a page count);
     (b) a DANGLING REFERENCE (a file, script, section, remark number or
         numbered check that does not exist);
     (c) a MISSING ENTRY in an index (a script that exists but is not
         listed in the index whose job is to list it);
     (d) a GENRE VIOLATION: content that describes the project's paperwork
         rather than the project. See the prohibitions below.
3. PROHIBITED, absolutely, in any state-genre document (README.md,
   CURRENT_STATE.md, folder READMEs, terminology.md, research_result.md,
   research_statement.md):
     - "Corrected on <date>", "settled on <date>", "was open through v5",
       "supersedes", "an earlier claim refuted", "Correction of record"
     - "Last updated: <date> (what changed ...)" footers. Git carries the
       history. A bare date stamp is acceptable where one already exists.
     - status blocks or sections restating another document's content
     - new sections that are not about the thing the document is about
     - denormalizing a table or ledger into a second copy elsewhere
   These documents state what IS. Nothing else.
4. Documents whose genre IS history keep their dates and status markers:
   the changelogs, the claims ledger (key_claims/README.md), the prompt
   logs, the dated reviews, the planning record. Do not "fix" those.
5. IMMUTABLE, not to be touched: prompt_logs/**, paper/reviews/**,
   paper/main_2026-*.tex, paper/v3_to_v4_summary.md, paper/main.tex,
   paper/automorphism_group_2026-07-12.tex, LICENSE.md.
